# Contributing

This guide describes the current setup and data workflow. See the [README](README.md) for the project purpose, AI disclosure, and current status.

## Setup

Install dependencies and start the current Create React App prototype:

```sh
npm install
npm start
```

Open http://localhost:3000. The app currently reads a local BattleScribe `.gst` file. The planned Next.js migration and Wahapedia-backed reminders interface have not been implemented yet.

## Project layout

| Path | Purpose |
| --- | --- |
| `src/App.js` | Current prototype page |
| `src/data/wh40k-10e/` | Existing BattleScribe game-system and catalogue files |
| `scripts/fetch-wahapedia-data.mjs` | Downloads the latest Wahapedia CSV exports |
| `src/data/wahapedia/` | Generated raw export snapshots and manifests |
| `build/` | Create React App production output; generated by `npm run build` |

## Refresh Wahapedia data

Run one ruleset:

```sh
npm run data:fetch -- --game 40k
npm run data:fetch -- --game aos
```

Or fetch both in sequence:

```sh
npm run data:fetch -- --game all
```

The command reads each Wahapedia data-export page, follows the export-specification workbook, and discovers its CSV links. The 40K page and workbook are configured explicitly; the AoS 4 workbook is discovered from its export page. If Wahapedia is inaccessible on your network, run the command from a network where the source is available.

Exports are written to `src/data/wahapedia/wh40k10ed/` and `src/data/wahapedia/aos4/`. Each directory contains the raw source files and a `manifest.json` with source URLs, fetch time, update marker, file sizes, and SHA-256 checksums. The manifest is sorted by filename. When the specification, `Last_update.csv`, and expected filenames are unchanged, a repeat run skips the full download.

The script downloads files sequentially with a short delay and stages a complete snapshot before replacing the previous directory. A failed download leaves the previous snapshot in place. The entire `src/data/wahapedia/` directory is ignored by Git: keep these raw exports and manifests local, and do not commit them.

Keep these CSVs as source snapshots: do not reorder rows or edit them by hand. The exports may use a nonstandard delimiter. Once the relevant tables and fields are chosen, parse them into a separate, deterministic JSON format for the app rather than making the source exports the app's permanent data model. Store any generated, app-ready JSON outside the ignored directory if it is intended to be versioned.

## Checks

Before committing a data or code change, run the checks that apply:

```sh
npm test -- --watchAll=false
npm run build
```

For an offline check of the downloader's options, run:

```sh
npm run data:fetch -- --help
```

## Deployment

The current site is published to GitHub Pages with:

```sh
npm run deploy
```

This runs the Create React App production build and publishes the `build/` directory to the `gh-pages` branch. The data fetch command is intentionally not part of deployment; refreshed exports are reviewed and committed separately.
